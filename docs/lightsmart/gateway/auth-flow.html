网关接入认证流程 ​

完整流程 ​

sequenceDiagram
    participant GW as 网关
    participant hapi
    participant EMQX
    participant mapi

    GW->>hapi: 1. POST /hotel/device/get_gateway_mqtt_info_sn
    hapi-->>GW: { mq_id, mq_pass, api_version, server_id }

    GW->>EMQX: 2. MQTT Connect (username=mq_id, password=mq_pass)
    EMQX->>mapi: 3. POST /mqtt/auth (HTTP Webhook)
    mapi->>mapi: 4. 查 license_tb 校验 mq_pass + status=1
    mapi-->>EMQX: { result: "allow" }

    EMQX->>mapi: 5. $SYS/.../connected (上线事件)
    mapi->>mapi: 6. 更新 device_tb.status=1 + device_mqtt_connect_tb

    GW->>EMQX: 7. 订阅 {topicL1}/{mq_id}/ble_in
    GW->>EMQX: 8. 订阅 {topicL1}/{mq_id}/system
    GW->>EMQX: 9. 订阅 {topicL1}/{mq_id}/at_in
    GW->>EMQX: 10. 发布 {topicL1}/{mq_id}/ble_out
    GW->>EMQX: 11. 发布 {topicL1}/{mq_id}/system_out

步骤说明 ​

步骤 1：获取 MQTT 连接信息 ​

网关通过 HTTP 请求 hapi 获取 MQTT 凭证，详见 MQTT 连接信息。

步骤 2-4：MQTT 连接认证 ​

网关使用 mq_id / mq_pass 连接 EMQX。EMQX 通过 HTTP Webhook 调用 mapi 认证，详见 MQTT 认证。

认证逻辑：

  • 查 license_tb 表，校验 mq_pass 匹配且 status=1
  • license_type=1（设备）的凭证才允许网关连接
  • 认证失败返回 { "result": "deny" }，EMQX 断开连接

步骤 5-6：上线事件处理 ​

mapi 订阅 EMQX $SYS 系统主题，处理设备上线事件，详见 设备上下线事件。

步骤 7-11：订阅与发布 ​

网关连接成功后，订阅下行主题、发布上行主题：

方向主题格式说明
订阅{topicL1}/{mq_id}/ble_inhex接收 BLE Mesh 控制指令
订阅{topicL1}/{mq_id}/systemJSON接收系统级指令（重启、OTA 等）
订阅{topicL1}/{mq_id}/at_inAT 命令接收串口指令
发布{topicL1}/{mq_id}/ble_outhex上报 BLE Mesh 设备状态
发布{topicL1}/{mq_id}/system_outJSON上报系统级状态
发布{topicL1}/{mq_id}/at_out字符串上报 AT 命令响应

topicL1 确定：api_version > 1 时用 mqtt{server_id}（如 mqtt1），否则用 module_code（如 6zcrzknc）。详见 MQTT 主题格式。

异步发布：ble_out 和 at_out 的 MQTT 发布通过网关内部事件队列异步执行，避免 BLE 数据接收或 UART 处理被 MQTT 发布阻塞。

mqtt_config 配置机制 ​

hapi module/login 接口在网关配网时下发 MQTT 服务器地址：

  • secret.onesite 为真：从 global_config_tb.mqtt_config（config_name='mqtt_config'）读取
  • 否则：使用硬编码 MQTT_SERVER_MAP（1/2/3 均指向 42.121.217.172）

分支条件是 secret.onesite（而非「生产/测试环境」）。依据 service-lightsmart-hapi/src/controller/module/module.js:232-268。

mqtt_config 的 config_content 格式：

json
{
  "port": 1883,
  "server": "192.168.3.164",
  "protocol": "mqtt",
  "keepalive": 60,
  "server_id": 1
}

根地址（base_url）与初启引导 ​

网关固件上电后先经引导服务取得主 API 根地址，再调 register / login / nodelist：

1. POST http://tiny.beancomm.net/api/module/module/get_time    → { "time": <unix 秒> }
2. POST http://tiny.beancomm.net/api/module/module/certificate → { "base_url": "http://hotel.chintiot.com/hapi/" }
3. 后续 register / login / nodelist 均以 base_url 为前缀拼接
  • 生效顺序：以 certificate 下发的 base_url 为准（实测 http://hotel.chintiot.com/hapi/），即线上主 API 为 hotel.chintiot.com。
  • 固件二进制内置默认 http://hotel.beancomm.net/api/v5/ 仅作初启兜底；该地址已下线（nginx 404），运行时会被 base_url 覆盖。
  • 调用方法须为 POST（GET 会因 express.text 不解析 body 而导致签名校验失败）。

修订（2026-09-26，A2 裁定）：明确「用 chintiot.com」——以 certificate 下发的 base_url 为准，hotel.beancomm.net 仅作初启兜底。依据 device-lightsmart-BCW018X/evidence/add_gateway_20260926_003201/result.md（A1 轮实测）与 融合对照账本.md:76。
